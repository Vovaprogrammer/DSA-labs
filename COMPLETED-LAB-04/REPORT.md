## 1. MergeSort со стабильным слиянием

### 1.1. Реализация

```python
def merge(left: list, right: list, key) -> list:
    """Стабильное слияние двух отсортированных списков в новый список.

    Стабильность: при равенстве ключей элемент из left идёт раньше.
    Сложность: Θ(len(left) + len(right)) по времени и по доп. памяти.
    """
    res = []
    i = j = 0
    while i < len(left) and j < len(right):
        # именно <=, а не <: при равных ключах первым берётся элемент из left
        if key(left[i]) <= key(right[j]):
            res.append(left[i])
            i += 1
        else:
            res.append(right[j])
            j += 1
    # одна из половин закончилась — хвост другой уже упорядочен
    res.extend(left[i:])
    res.extend(right[j:])
    return res


def merge_sort(a: list, key=lambda x: x) -> list:
    """MergeSort: возвращает новый отсортированный список, вход не меняется.

    Сложность: Θ(n log n) в любом случае; доп. память Θ(n).
    """
    if len(a) <= 1:
        return list(a)  # копия: результат не должен быть тем же объектом, что вход
    mid = len(a) // 2
    return merge(merge_sort(a[:mid], key), merge_sort(a[mid:], key), key)
```

Массив делится пополам, половины сортируются рекурсивно и сливаются двумя указателями: на каждом шаге в результат идёт меньший из `left[i]` и `right[j]`, остаток непустой половины добавляется целиком. `key` — функция ключа, как у `sorted()`; вход не меняется.

- **Время:** `T(n) = 2·T(n/2) + Θ(n)` → **Θ(n log n) во всех случаях**: деление пополам не зависит от данных, на каждом из `log₂ n` уровней переносятся все `n` элементов. От входа зависит только число сравнений — на отсортированном входе ровно `(n/2)·log₂ n`, на случайном около `n·log₂ n` (счётчиком при `n = 1024`: 5 120 и 8 971).
- **Память:** Θ(n) дополнительно (результат слияния и срезы половин), стек рекурсии O(log n) — 17 уровней при `n = 10⁵`. Сортировка не in-place.

### 1.2. Тест стабильности

Стабильность даёт условие `<=` в `merge`: при равных ключах берётся элемент из левой половины, а она во входе целиком стоит раньше правой.

```python
def check_merge_stability() -> None:
    rng = random.Random(0)
    for _ in range(200):
        pairs = [(rng.randint(0, 5), i) for i in range(rng.randint(0, 100))]
        got = merge_sort(pairs, key=lambda p: p[0])
        for prev, cur in zip(got, got[1:]):
            expect(
                prev[0] < cur[0] or (prev[0] == cur[0] and prev[1] < cur[1]),
                f"merge_sort нестабилен: {prev} стоит перед {cur}",
            )
        expect(
            got == sorted(pairs, key=lambda p: p[0]),
            "merge_sort нестабилен: при равных ключах нарушен исходный порядок номеров",
        )
```

Пары `(ключ, номер)` сортируются только по ключу; ключи из `[0, 5]`, поэтому равных много. Проверяется, что у соседей номер растёт при равном ключе, и что результат совпадает со стабильным `sorted()`. Тест входит в `self_check` и проходит.

Демонстрация (`merge_stability_demo`) на входе `[(2, 0), (1, 1), (2, 2), (0, 3), (1, 4), (2, 5), (0, 6), (1, 7)]` и эксперимент с `<` вместо `<=`:

| Ключ | Номера во входе | После `merge_sort` (`<=`) | При `<` |
| --- | --- | --- | --- |
| 0 | 3, 6 | 3, 6 | **6, 3** |
| 1 | 1, 4, 7 | 1, 4, 7 | **7, 4, 1** |
| 2 | 0, 2, 5 | 0, 2, 5 | **5, 2, 0** |

С `<` порядок равных полностью переворачивается, и тест падает (`(0, 45) стоит перед (0, 44)`), хотя обычная проверка на целых числах проходит — равные числа неотличимы. Поэтому стабильность проверяется именно на парах.
