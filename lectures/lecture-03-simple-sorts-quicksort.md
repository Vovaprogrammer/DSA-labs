Дисциплина «Структуры и алгоритмы обработки данных», раздел 2. Темы: задача сортировки, инверсии и стабильность, сортировки пузырьком, вставками и выбором, нижняя граница для перестановок соседей, быстрая сортировка (QuickSort): разбиения Ломуто и Хоара, лучший, худший и средний случай, случайный опорный элемент, равные ключи и глубина стека, quickselect.

## 1. Задача сортировки

**Определение.** Сортировка — перестановка элементов последовательности, после которой их ключи идут в неубывающем порядке: a[0] ≤ a[1] ≤ … ≤ a[n − 1]. Результат состоит из тех же элементов, что и вход, — меняется только их порядок.

Ключ — то, по чему сравнивают элементы: число, строка или поле записи, например `key=lambda s: s.group`. Все алгоритмы этой лекции — сортировки сравнением: о данных они узнают только из ответов на вопрос «a[i] < a[j]?». Сортировка на месте переставляет элементы внутри массива и берёт лишь O(1) или O(log n) дополнительной памяти.

Результат сортировки проверяют по двум условиям:

1. он упорядочен: res[i] ≤ res[i + 1] для всех i;
2. он перестановка входа: те же элементы столько же раз, `Counter(res) == Counter(a)`.

Нужны оба условия. Функция `return []` всегда выдаёт упорядоченный список, а `return a` — всегда перестановку входа, но ни та, ни другая не сортирует.

Упорядоченные данные окупают затраты на сортировку: в упорядоченном массиве поиск идёт за Θ(log n), дубликаты находятся за один проход, а медиана берётся по индексу.

## 2. Инверсии и стабильность

**Определение.** Инверсия — пара позиций i < j, в которых элементы стоят в неправильном порядке: a[i] > a[j]. Число инверсий показывает, насколько массив далёк от упорядоченного.

В массиве [5, 2, 4, 6, 1, 3] девять инверсий; записанные значениями, это пары (5, 2), (5, 4), (5, 1), (5, 3), (2, 1), (4, 1), (4, 3), (6, 1), (6, 3). У упорядоченного массива инверсий нет, у обратного инверсию образует каждая пара — n(n − 1)/2. В случайной перестановке каждая пара стоит неправильно с вероятностью ½, поэтому инверсий в среднем n(n − 1)/4: при n = 1000 это 249 750.

Обмен двух **соседних** элементов меняет число инверсий не больше чем на одну. Пары с любым третьим элементом z после обмена x и y сохраняют порядок; меняется только сама пара (x, y): если x > y, инверсия исчезает, если x < y — появляется, при x = y ничего не меняется. Поэтому алгоритму, который переставляет только соседей, нужно не меньше обменов, чем инверсий во входе.

**Определение.** Стабильная (устойчивая) сортировка — сортировка, которая сохраняет исходный взаимный порядок элементов с равными ключами.

Пусть пары (2, a), (1, b), (2, c), (1, d) сортируются по первому числу. Стабильная сортировка выдаст (1, b), (1, d), (2, a), (2, c): b осталась перед d, а a — перед c, как во входе. Сортировка выбором (раздел 3) выдаёт (1, b), (1, d), (2, c), (2, a) — a и c поменялись местами.

Стабильность нужна при сортировке по нескольким ключам: сначала сортируют по второстепенному ключу (фамилия), затем стабильно по главному (группа), и внутри каждой группы фамилии остаются по алфавиту. В Python `sorted` и `list.sort` стабильны — это гарантия документации. Для чисел без меток стабильность не видна: равные числа неотличимы.

## 3. Пузырёк, вставки и выбор

```python
def bubble_sort(a):
    n = len(a)
    for i in range(n - 1):
        swapped = False
        for j in range(n - 1 - i):
            if a[j] > a[j + 1]:
                a[j], a[j + 1] = a[j + 1], a[j]
                swapped = True
        if not swapped:          # обменов не было: массив упорядочен
            break
```

Проход сравнивает соседей слева направо и меняет их местами, если они стоят неправильно; самый большой элемент «всплывает» в конец. Инвариант: после i проходов последние i элементов — самые большие и стоят на своих местах. В худшем случае сравнений (n − 1) + … + 1 = n(n − 1)/2, обменов всегда ровно столько, сколько инверсий: каждый обмен соседей при a[j] > a[j + 1] убирает одну инверсию. Благодаря флагу `swapped` упорядоченный вход обрабатывается за один проход из n − 1 сравнений. Сортировка стабильна: строгое «>» не трогает равные элементы.

```python
def insertion_sort(a):
    for i in range(1, len(a)):
        x = a[i]
        j = i - 1
        while j >= 0 and a[j] > x:
            a[j + 1] = a[j]       # сдвиг вправо
            j -= 1
        a[j + 1] = x
```

Инвариант сортировки вставками: перед шагом i префикс a[0..i − 1] упорядочен — как карты в руке. Каждый сдвиг убирает одну инверсию, поэтому **сдвигов ровно столько, сколько инверсий**, а время равно Θ(n + число инверсий): от n − 1 сравнений на упорядоченном входе до n(n − 1)/2 на обратном, в среднем около n²/4. Сортировка стабильна: элемент не перепрыгивает через равный, потому что сдвиг идёт только при строгом `a[j] > x`.

```python
def selection_sort(a):
    n = len(a)
    for i in range(n - 1):
        m = i                     # индекс минимума
        for j in range(i + 1, n):
            if a[j] < a[m]:
                m = j
        a[i], a[m] = a[m], a[i]
```

Инвариант сортировки выбором: a[0..i − 1] — i наименьших элементов в окончательном порядке. Сравнений **всегда** n(n − 1)/2: внутренний цикл не зависит от данных. Обменов не больше n − 1 — меньше, чем у других простых сортировок, поэтому выбор полезен, когда запись элемента дорогая. Сортировка **нестабильна**: на входе (2, a), (2, b), (1, c) минимум (1, c) меняется местами с (2, a), получается (1, c), (2, b), (2, a), и a уходит за b.

### Разбор 1. Счётчики на массиве [5, 2, 4, 6, 1, 3]

В массиве 9 инверсий. Сортировка вставками по шагам:

| i | x | сравнений | сдвигов | остановка | массив после шага |
| --- | --- | --- | --- | --- | --- |
| 1 | 2 | 1 | 1 | граница j < 0 | 2, 5, 4, 6, 1, 3 |
| 2 | 4 | 2 | 1 | 2 ≤ 4 | 2, 4, 5, 6, 1, 3 |
| 3 | 6 | 1 | 0 | 5 ≤ 6 | 2, 4, 5, 6, 1, 3 |
| 4 | 1 | 4 | 4 | граница j < 0 | 1, 2, 4, 5, 6, 3 |
| 5 | 3 | 4 | 3 | 2 ≤ 3 | 1, 2, 3, 4, 5, 6 |

Итого 12 сравнений и 9 сдвигов: сравнений столько же, сколько сдвигов, плюс по одному на каждую остановку на сравнении (9 + 3). Пузырёк делает 15 сравнений и 9 обменов: последний обмен происходит на пятом проходе, поэтому досрочного выхода нет, 5 + 4 + 3 + 2 + 1 = 15. Выбор делает 15 = 6·5/2 сравнений, как и на любом входе из шести элементов, и 3 обмена, если не считать обмены элемента с самим собой.

Время всех трёх сортировок на случайном входе растёт как n². Если t ≈ c·nᵏ, то в логарифмических шкалах график времени — прямая с наклоном k: при удвоении n время растёт в 2ᵏ раз, у квадратичных сортировок — вчетверо. На упорядоченном входе вставки и пузырёк с флагом работают за линейное время, а выбор — по-прежнему за квадратичное.

## 4. Предел простых сортировок

### Разбор 2. Среднее число инверсий — n(n − 1)/4

```
Перестановка a и её разворот a′:
пара значений x > y стоит неправильно ровно в одной из них
⇒ inv(a) + inv(a′) = n(n − 1)/2
Все перестановки разбиваются на такие пары ⇒ в среднем inv = n(n − 1)/4
```

Пример: в [5, 2, 4, 6, 1, 3] девять инверсий, в развороте [3, 1, 6, 4, 2, 5] — шесть, и 9 + 6 = 15 = 6·5/2.

Отсюда вывод: если алгоритм переставляет только **соседние** элементы, на случайном входе ему нужно в среднем не меньше n(n − 1)/4 обменов, потому что каждый обмен убирает не больше одной инверсии. Это Θ(n²): пузырёк и вставки быстрее не станут, каким бы хитрым ни был порядок проходов.

Выход — дальние перестановки. В массиве [4, 3, 2, 1] шесть инверсий; один обмен крайних элементов даёт [1, 3, 2, 4], где осталась одна. Один дальний обмен убрал пять инверсий. На дальних перестановках построены быстрые сортировки: QuickSort, сортировка слиянием и сортировка кучей.

Простые сортировки при этом не бесполезны. Вставки работают за Θ(n + инверсий), поэтому ими сортируют маленькие массивы и почти упорядоченные данные; так досортировывают короткие участки внутри Timsort и гибридных реализаций QuickSort. Выбор уместен, когда дорога запись: обменов не больше n − 1. Пузырёк остаётся учебным: на тех же данных он проигрывает вставкам.

## 5. QuickSort и разбиение Ломуто

**Определение.** Разбиение отрезка относительно опорного элемента p — перестановка, после которой p стоит на некоторой позиции m, все элементы левее m меньше p, а все правее — не меньше p.

QuickSort выбирает опорный элемент, разбивает отрезок — опорный встаёт на своё окончательное место m — и рекурсивно сортирует части слева и справа от m. Объединять ничего не нужно: после разбиения части уже стоят на своих местах.

```python
def quick_sort(a, lo, hi):
    if lo >= hi:                  # 0 или 1 элемент
        return
    m = partition(a, lo, hi)
    quick_sort(a, lo, m - 1)
    quick_sort(a, m + 1, hi)
```

Это «разделяй и властвуй» из [Лекции 2](lecture-02-recursion-linear-structures.md), только вся работа выполняется при разделении. У сортировки слиянием наоборот: делит она даром, а работает при слиянии. QuickSort предложил Тони Хоар в 1959 году. Сортировка идёт на месте: дополнительная память нужна только для стека вызовов.

```python
def partition(a, lo, hi):
    p = a[hi]                     # опорный — последний элемент
    i = lo                        # начало зоны «≥ p»
    for j in range(lo, hi):
        if a[j] < p:
            a[i], a[j] = a[j], a[i]
            i += 1
    a[i], a[hi] = a[hi], a[i]
    return i                      # место p
```

Инвариант перед шагом j: a[lo..i − 1] < p, a[i..j − 1] ≥ p, a[j..hi − 1] ещё не просмотрены, p лежит в a[hi]. Если a[j] < p, он меняется с первым элементом зоны «≥ p», и обе зоны сдвигаются; в конце p меняется с a[i] и встаёт между зонами. Отрезок из n элементов требует ровно n − 1 сравнений и O(1) дополнительной памяти: разбиение стоит Θ(n). Схему предложил Нико Ломуто; её удобно доказывать, поэтому она есть во многих учебниках.

Пример: массив [6, 3, 8, 1, 9, 2, 7, 5], опорный p = 5.

| j | действие | i | массив после шага |
| --- | --- | --- | --- |
| 0 | 6 ≥ 5: пропуск | 0 | 6, 3, 8, 1, 9, 2, 7, 5 |
| 1 | 3 < 5: обмен a[0] и a[1] | 1 | 3, 6, 8, 1, 9, 2, 7, 5 |
| 2 | 8 ≥ 5: пропуск | 1 | 3, 6, 8, 1, 9, 2, 7, 5 |
| 3 | 1 < 5: обмен a[1] и a[3] | 2 | 3, 1, 8, 6, 9, 2, 7, 5 |
| 4 | 9 ≥ 5: пропуск | 2 | 3, 1, 8, 6, 9, 2, 7, 5 |
| 5 | 2 < 5: обмен a[2] и a[5] | 3 | 3, 1, 2, 6, 9, 8, 7, 5 |
| 6 | 7 ≥ 5: пропуск | 3 | 3, 1, 2, 6, 9, 8, 7, 5 |
| — | p на место: обмен a[3] и a[7] | 3 | 3, 1, 2, 5, 9, 8, 7, 6 |

Итог: m = 3, пятёрка на своём месте, дальше сортируются a[0..2] и a[4..7]. Сравнений 7 = n − 1, обменов 4.

## 6. Разбиение Хоара

```python
def partition_hoare(a, lo, hi):
    p = a[lo]
    i, j = lo - 1, hi + 1
    while True:
        i += 1
        while a[i] < p:
            i += 1
        j -= 1
        while a[j] > p:
            j -= 1
        if i >= j:
            return j
        a[i], a[j] = a[j], a[i]
```

Два индекса идут навстречу друг другу: левый останавливается на элементе ≥ p, правый — на элементе ≤ p, и эти два элемента меняются местами. Результат другой, чем у Ломуто: a[lo..j] ≤ p ≤ a[j + 1..hi], а опорный не обязательно стоит на своём месте. Поэтому рекурсия идёт по отрезкам (lo, j) и (j + 1, hi).

На том же массиве [6, 3, 8, 1, 9, 2, 7, 5] с опорным p = 6 (первый элемент) разбиение делает два обмена — a[0] = 6 с a[7] = 5 и a[2] = 8 с a[5] = 2 — и возвращает j = 3: получается [5, 3, 2, 1, 9, 8, 7, 6], левая часть a[0..3] ≤ 6, правая a[4..7] ≥ 6. У Ломуто на этом массиве обменов было четыре.

На случайных массивах из 10⁴ элементов схема Хоара делает в среднем около 31 500 обменов против 85 400 у Ломуто — почти втрое меньше. Индексы останавливаются и на элементах, равных p, поэтому массив из равных элементов делится пополам. Цена — хрупкие границы: рекурсия по (lo, j − 1) или `<=` вместо `<` в условиях циклов приводят к бесконечной рекурсии или выходу за массив.

## 7. Лучший, худший и средний случай

Если каждое разбиение делит отрезок пополам, то T(n) = 2T(n/2) + Θ(n), и по второму случаю мастер-теоремы T(n) = Θ(n log n) — как у сортировки слиянием. Если же каждый раз отделяется только опорный (части 0 и n − 1), то T(n) = T(n − 1) + Θ(n), и сравнений (n − 1) + (n − 2) + … + 1 = n(n − 1)/2 = Θ(n²), как у пузырька.

Худший случай возникает, когда опорный — первый или последний элемент, а вход **уже упорядочен**, и это самый частый вход на практике. Кроме времени, страдает память: глубина рекурсии доходит до n, и при n ≈ 1000 Python завершает работу с `RecursionError`.

Идеальный баланс не нужен. Если каждое разбиение делит отрезок в пропорции 1 : 9, на каждом уровне дерева рекурсии работы по-прежнему не больше n, а самая длинная ветвь заканчивается, когда n·(9/10)ᵏ = 1, то есть k = log₁₀/₉ n = log₂ n / log₂(10/9) ≈ 6,58·log₂ n. Константа выросла, порядок тот же — Θ(n log n). Любая фиксированная пропорция 1 : q даёт Θ(n log n); квадрат получается, только если от отрезка раз за разом отрезается O(1) элементов.

### Разбор 3. Среднее число сравнений — ≈ 1,39·n·log₂ n

Пусть опорный элемент выбирается случайно, а z₁ < z₂ < … < zₙ — элементы массива в порядке возрастания. Элементы zᵢ и zⱼ (i < j) сравниваются тогда и только тогда, когда первым опорным среди zᵢ, zᵢ₊₁, …, zⱼ стал zᵢ или zⱼ: если раньше выбран элемент между ними, zᵢ и zⱼ разойдутся по разным частям и больше не встретятся. Каждая пара сравнивается не больше одного раза, потому что сравнивают только с опорным, а он в дальнейшую рекурсию не попадает.

```
P(zᵢ и zⱼ сравниваются) = 2/(j − i + 1)
E[C] = Σ по парам 2/(j − i + 1) ≤ 2n·(½ + ⅓ + … + 1/n) < 2n·ln n
Точно: E[C(n)] = 2(n + 1)·H(n) − 4n,  H(n) = 1 + ½ + … + 1/n ≈ ln n
2·ln n = 2·ln 2·log₂ n ≈ 1,386·log₂ n
```

Проверка при n = 3: пары (z₁, z₂) и (z₂, z₃) сравниваются с вероятностью 1, пара (z₁, z₃) — с вероятностью 2/3; сумма 8/3, и по формуле 2·4·(1 + ½ + ⅓) − 12 = 8/3. Сравнения здесь считаются как у Ломуто: n − 1 на разбиение.

| n | ожидаемое число сравнений | n·log₂ n | худший случай |
| --- | --- | --- | --- |
| 1 000 | 10 986 | 9 966 | 499 500 |
| 10 000 | 155 772 | 132 877 | 49 995 000 |
| 1 000 000 | ≈ 24,8 млн | ≈ 19,9 млн | ≈ 5·10¹¹ |

Точная сумма меньше главного члена 2n·ln n примерно на 2,8n, поэтому при n = 10⁶ выходит около 1,24·n·log₂ n сравнений. Проверка экспериментом: 200 запусков при n = 1000 дают в среднем 10 984 сравнения, от 9 660 до 13 705.

## 8. Случайный опорный, равные ключи и глубина стека

Анализ среднего случая предполагает случайный вход, а реальные данные не случайны: часто они уже почти упорядочены, и с фиксированным опорным такой вход даёт Θ(n²). Случайный опорный переносит случайность внутрь алгоритма: оценка ≈ 1,39·n·log₂ n становится ожидаемой для **любого** входа. Плохой вход подобрать нельзя, неудачными бывают только броски. Худший случай Θ(n²) остаётся, но для него нужно много раз подряд вытянуть почти крайний элемент.

```python
k = rng.randrange(lo, hi + 1)     # правая граница не включается
a[k], a[hi] = a[hi], a[k]
m = partition(a, lo, hi)
```

Генератор `rng` передают снаружи, чтобы запуск воспроизводился по seed. Есть и другие способы выбрать опорный: медиана трёх (первого, среднего и последнего элементов) спасает от упорядоченного входа, но не от специально подобранного; introsort при глубине рекурсии больше 2·log₂ n переходит на сортировку кучей и гарантирует O(n log n) — так устроен `std::sort` в C++.

**Много равных ключей.** Если все элементы равны, разбиение Ломуто каждый раз отделяет один элемент: n(n − 1)/2 сравнений, и случайный опорный не помогает. Трёхчастное разбиение (Э. Дейкстра) собирает элементы, равные p, в середине отрезка — зоны «< p», «= p», «> p», — и в рекурсию идут только крайние зоны. На массиве [3, 5, 1, 3, 4, 2, 3] с p = 3 оно за 7 сравнений получает [1, 2, 3, 3, 3, 4, 5]: три тройки сразу на своих местах. Массив из 4000 равных элементов Ломуто сортирует около 0,3 с, трёхчастное разбиение — за доли миллисекунды.

**Глубина стека.** Если рекурсивно сортировать меньшую часть, а большую — циклом, глубина рекурсии не превышает log₂ n даже в худшем случае: рекурсивный вызов получает не больше половины отрезка. Время от этого не меняется — меняется только память.

```python
while hi - lo > 0:
    m = partition(a, lo, hi)
    if m - lo < hi - m:
        sort(a, lo, m - 1)        # меньшая часть — рекурсией
        lo = m + 1
    else:
        sort(a, m + 1, hi)
        hi = m - 1
```

**Малые отрезки.** На 10–20 элементах рекурсия дороже самой работы, поэтому короткие отрезки досортировывают вставками.

## 9. Сортировка в Python и quickselect

```python
b = sorted(a)                     # новый список
a.sort()                          # на месте, возвращает None
a = a.sort()                      # ошибка: в a окажется None
sorted(people, key=lambda p: (p.group, p.name))
sorted(words, key=len, reverse=True)
```

Ключ-кортеж сравнивается по порядку полей: сначала группа, при равенстве — имя; `key` вычисляется один раз на элемент. `sorted` и `list.sort` реализуют Timsort: он находит во входе готовые упорядоченные участки — серии, короткие серии дополняет вставками до 32–64 элементов и затем сливает. Timsort стабилен, работает за O(n log n) в худшем случае и за Θ(n) на упорядоченном входе. При n = 10⁶ собственный QuickSort на Python тратит около 2 с, а `sorted` — около 0,1 с: разница в основном в том, что `sorted` написан на C, асимптотика та же. В рабочем коде свою сортировку не пишут; собственные реализации нужны, чтобы понимать цену операций, проверять чужой код и проходить собеседования.

| Алгоритм | Лучший | Средний | Худший | Память | Стабилен |
| --- | --- | --- | --- | --- | --- |
| Пузырёк (с выходом) | Θ(n) | Θ(n²) | Θ(n²) | O(1) | да |
| Вставки | Θ(n) | Θ(n²) | Θ(n²) | O(1) | да |
| Выбор | Θ(n²) | Θ(n²) | Θ(n²) | O(1) | нет |
| QuickSort, случайный опорный | Θ(n log n) | Θ(n log n) | Θ(n²) | O(log n)* | нет |
| Timsort (`sorted`) | Θ(n) | Θ(n log n) | Θ(n log n) | O(n) | да |

\* Память QuickSort — стек вызовов: в среднем O(log n), в худшем Θ(n); если рекурсивно сортировать меньшую часть — O(log n) всегда. «Средний» у QuickSort — ожидание по случайным выборам опорного для любого входа.

Разбиение полезно и без сортировки. Чтобы найти k-й по величине элемент (например, медиану), quickselect разбивает отрезок и продолжает только в той части, где лежит позиция k:

```python
def select(a, k, lo, hi):         # k-й по величине, k от 0
    while True:
        m = random_partition(a, lo, hi)
        if k == m:
            return a[m]
        if k < m:
            hi = m - 1
        else:
            lo = m + 1
```

Если части каждый раз примерно вдвое меньше, работа — геометрическая прогрессия: n + n/2 + n/4 + … < 2n. Со случайным опорным часть в среднем уменьшается не вдвое, а в 4/3 раза, оценка становится 4n, но остаётся Θ(n); худший случай — Θ(n²). Так устроены `numpy.partition` и `numpy.median` (алгоритм introselect) и `std::nth_element` в C++, а `statistics.median` в Python сортирует данные целиком — Θ(n log n).

Методика замеров — [`docs/reproducibility.md`](../docs/reproducibility.md).

Правдоподобный на вид QuickSort со списковыми включениями содержит две ошибки:

```python
def quick_sort(a):
    if len(a) <= 1:
        return a
    p = a[0]
    left = [x for x in a if x < p]
    right = [x for x in a if x > p]
    return quick_sort(left) + [p] + quick_sort(right)
```

`quick_sort([3, 1, 3])` возвращает [1, 3]: копии опорного потеряны, и это ловит проверка «перестановка входа». Опорный `a[0]` на упорядоченном входе даёт Θ(n²) и `RecursionError` — это видно только по замерам и глубине рекурсии. Другие типичные дефекты: `>=` вместо `>` во вставках ломает стабильность; флаг `swapped`, сброшенный не в том месте, лишает пузырёк лучшего случая; разбиение Ломуто на массиве из равных ключей работает за Θ(n²).
