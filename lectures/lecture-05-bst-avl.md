# Лекция 5. Бинарные деревья поиска и AVL-деревья

Дисциплина «Структуры и алгоритмы обработки данных», раздел 3. Темы: динамическое множество, двоичные деревья и их обходы, бинарное дерево поиска (BST): поиск, вставка, преемник, удаление и проверка инварианта; высота дерева на случайном и упорядоченном входе; AVL-деревья: показатель сбалансированности, оценка высоты, повороты, вставка и удаление.

## 1. Задача: динамическое множество

**Определение.** Динамическое множество — набор ключей, который меняется во время работы программы. Основные операции — поиск, вставка и удаление ключа; часто нужны также минимум, максимум и следующий по величине ключ.

| Структура | Поиск | Вставка | Удаление | Минимум, следующий |
| --- | --- | --- | --- | --- |
| Упорядоченный массив | O(log n) | Θ(n) | Θ(n) | O(1), O(log n) |
| Связный список | Θ(n) | O(1) | Θ(n) | Θ(n) |
| Хеш-таблица (лекция 8) | O(1) в среднем | O(1) в среднем | O(1) в среднем | Θ(n) |
| Сбалансированное дерево поиска | O(log n) | O(log n) | O(log n) | O(log n) |

Упорядоченный массив быстро ищет, но медленно меняется: вставка в начало массива из миллиона элементов сдвигает миллион элементов. Связный список — наоборот. Дерево поиска объединяет оба свойства: спуск по дереву повторяет бинарный поиск, а вставка и удаление меняют несколько ссылок. Хеш-таблица быстрее, но порядка ключей не хранит, а он нужен в индексах СУБД (поиск по диапазону), в очередях событий по времени, в словарях с обходом по алфавиту.

## 2. Двоичные деревья

**Определение.** Двоичное дерево — либо пустое дерево, либо узел-корень, у которого есть левое и правое поддеревья, каждое из которых — двоичное дерево.

Определение рекурсивное, поэтому и большинство алгоритмов на деревьях рекурсивны: обработать корень и повторить для поддеревьев. Корень — узел без родителя; лист — узел без детей; остальные узлы — внутренние. Любой узел вместе со всеми потомками образует поддерево. Каждый ребёнок двоичного дерева — либо левый, либо правый: дерево, где у корня только левый ребёнок, и дерево, где только правый, различаются.

Глубина узла — число рёбер на пути от корня к нему; узлы одной глубины образуют уровень. Высота дерева — наибольшая глубина узла. Высоту считаем в рёбрах, как в лабораторной работе № 5: у пустого дерева она равна −1, у дерева из одного узла — 0. В некоторых книгах высоту считают в узлах, и тогда все значения на единицу больше.

На уровне k не больше 2ᵏ узлов, поэтому в дереве высоты h не больше 1 + 2 + … + 2ʰ = 2ʰ⁺¹ − 1 узлов. Отсюда дерево из n узлов не может быть ниже ⌊log₂ n⌋.

## 3. Бинарное дерево поиска

**Определение.** Бинарное дерево поиска (BST) — двоичное дерево, в узлах которого хранятся ключи, причём для каждого узла все ключи его левого поддерева меньше ключа узла, а все ключи правого поддерева — больше.

```python
class Node:
    def __init__(self, key):
        self.key = key
        self.left = None      # ключи меньше key
        self.right = None     # ключи больше key
```

Условие касается **всех** потомков, а не только детей. В дереве, полученном вставками 8, 3, 10, 1, 6, 14, 4, 7, 13, у корня 8 дети 3 и 10, у тройки — 1 и 6, у шестёрки — 4 и 7, у десятки только правый ребёнок 14, а у 14 — левый ребёнок 13. Семёрка — правый ребёнок шестёрки, но лежит и в левом поддереве корня, поэтому обязана быть меньше восьми. Если расставить узлы над числовой прямой, каждый над своим ключом, проекции пойдут по возрастанию: 1, 3, 4, 6, 7, 8, 10, 13, 14 — всё, что левее узла, меньше его ключа.

Одни и те же ключи можно разложить в дерево поиска многими способами; форма дерева зависит от порядка вставок (раздел 9). В ЛР 5 ключи различны: повторная вставка существующего ключа ничего не меняет.

## 4. Поиск и вставка

```python
def search(self, key):
    cur = self.root
    while cur is not None:
        if key == cur.key:
            return True
        if key < cur.key:
            cur = cur.left        # меньшие ключи — слева
        else:
            cur = cur.right       # большие — справа
    return False
```

Поиск начинается с корня: если ключ меньше ключа узла, он может быть только в левом поддереве, если больше — только в правом. В дереве из раздела 3 поиск 7 проходит путь 8 → 3 → 6 → 7 — четыре сравнения. Поиск 5 проходит 8 → 3 → 6 → 4 и упирается в пустую правую ссылку четвёрки — ключа нет. За шаг поиск опускается на уровень, поэтому сравнений не больше h + 1, а время — **O(h)**, где h — высота дерева. Минимум — самый левый узел (спуск по левым ссылкам до конца), максимум — самый правый; это тоже O(h).

```python
def _insert(node, key):
    if node is None:
        return Node(key)          # новый лист
    if key < node.key:
        node.left = _insert(node.left, key)
    elif key > node.key:
        node.right = _insert(node.right, key)
    return node                   # равный ключ — без изменений

# метод класса: self.root = _insert(self.root, key)
```

Вставка устроена как неудачный поиск: спуск упирается в пустую ссылку, и на её место подвешивается новый узел. Новый ключ всегда становится листом, остальные узлы не перемещаются; время — O(h). Вставка 5 в дерево из раздела 3 проходит 8 → 3 → 6 → 4 и подвешивает пятёрку правым ребёнком четвёрки.

Рекурсивная вставка имеет глубину h. Если вставлять ключи 1, 2, 3, … по возрастанию, дерево вытягивается в линию, и при пределе рекурсии CPython в 1000 кадров вставка падает с `RecursionError` уже на 999-м ключе. Итеративная вставка делает тот же спуск циклом, запоминая предыдущий узел — будущего родителя, — и в конце подвешивает новый узел к нему слева или справа.

## 5. Обходы

Обход посещает все узлы дерева. Три рекурсивных обхода различаются только моментом, когда обрабатывается сам узел:

```python
def in_order(node, out):
    if node is not None:
        in_order(node.left, out)
        out.append(node.key)      # между поддеревьями
        in_order(node.right, out)
```

В pre-order строка `out.append` стоит до рекурсивных вызовов, в post-order — после них. Обход по уровням (level-order) не рекурсивный: корень кладут в очередь `collections.deque`, затем извлекают узел, обрабатывают его и кладут в очередь его детей, пока очередь не опустеет.

Для дерева, полученного вставками 4, 2, 6, 1, 3, 5, 7 (корень 4, его дети 2 и 6, внизу 1, 3, 5, 7):

| Обход | Порядок | Результат | Применение |
| --- | --- | --- | --- |
| in-order | левое, узел, правое | 1 2 3 4 5 6 7 | ключи по возрастанию, проверка BST |
| pre-order | узел, левое, правое | 4 2 1 3 6 5 7 | копирование и сохранение дерева |
| post-order | левое, правое, узел | 1 3 2 5 7 6 4 | высоты и размеры, удаление дерева |
| level-order | по уровням, очередь | 4 2 6 1 3 5 7 | вывод по уровням |

Если вставить ключи в порядке pre-order в пустое дерево, получится точно такое же дерево: каждый узел вставляется раньше своих потомков. Post-order нужен, когда узлу требуются результаты детей: высота, число узлов, освобождение памяти. Зеркальный in-order (правое, узел, левое) выдаёт ключи по убыванию. Каждый обход посещает каждый узел один раз — Θ(n) при любой форме дерева, а рекурсивным обходам нужен стек глубины h.

## 6. Порядок ключей и преемник

In-order выводит ключи BST по возрастанию. Доказательство — индукция по высоте: ключи левого поддерева меньше ключа узла и выводятся раньше него, ключи правого — больше и выводятся позже, а каждое поддерево по предположению индукции выводится упорядоченно. Верно и обратное: если in-order строго возрастает, дерево — BST. Отсюда сортировка деревом: n вставок и обход in-order.

Преемник — следующий по величине ключ. Его находят по одному из двух правил:

1. есть правое поддерево — преемник равен его минимуму: шаг вправо, затем влево до конца;
2. правого поддерева нет — преемник равен ближайшему предку, в левом поддереве которого лежит узел.

В дереве из раздела 3 преемник 10 — минимум правого поддерева, 13. У семёрки правого поддерева нет: поднимаясь, мы приходим к шестёрке справа, к тройке тоже справа, а к восьмёрке — слева, поэтому преемник 7 — это 8. Без ссылок на родителя преемника ищут спуском от корня, запоминая последний узел, где спуск ушёл влево:

```python
def successor(root, key):
    cur, cand = root, None
    while cur is not None:
        if key < cur.key:
            cand = cur            # ушли влево
            cur = cur.left
        else:
            cur = cur.right
    return cand
```

Время — O(h). Преемник нужен при удалении и в запросах диапазона: чтобы выдать все ключи из [a, b], спускаются к a и переходят к преемнику, пока не перейдут b, — O(h + k) для k найденных ключей.

## 7. Удаление

Сначала узел нужно найти. Дальше возможны три случая:

1. **лист** — в родителе ссылка на узел заменяется на `None`;
2. **один ребёнок** — на место узла встаёт его ребёнок вместе со всем поддеревом;
3. **два ребёнка** — в узел записывается ключ преемника (минимума правого поддерева), а сам преемник удаляется из правого поддерева.

```python
def _delete(node, key):
    if node is None:
        return None                       # ключа нет
    if key < node.key:
        node.left = _delete(node.left, key)
    elif key > node.key:
        node.right = _delete(node.right, key)
    elif node.left is None:               # случаи 1 и 2
        return node.right
    elif node.right is None:
        return node.left
    else:                                 # случай 3
        s = node.right
        while s.left is not None:
            s = s.left                    # s — преемник
        node.key = s.key
        node.right = _delete(node.right, s.key)
    return node

# метод класса: self.root = _delete(self.root, key)
```

Функция возвращает новый корень поддерева, и родитель записывает его в свою ссылку; так же обрабатывается и удаление корня всего дерева. Во втором случае порядок не нарушается: поднятое поддерево и раньше лежало по нужную сторону от каждого предка.

В третьем случае нужен ключ, который больше всех ключей левого поддерева и меньше всех остальных ключей правого. Таких ключей ровно два: преемник (минимум правого поддерева) и предшественник (максимум левого); годится любой из них. У преемника нет левого ребёнка — иначе минимум был бы левее, — поэтому его удаление сводится к первому или второму случаю. Спуск к удаляемому узлу и дальше к преемнику — один путь вниз от корня, поэтому удаление стоит O(h).

### Разбор 1. Удаление корня, у преемника которого есть ребёнок

Удалим 8 из дерева раздела 3. У корня два ребёнка; минимум правого поддерева — 10: шаг вправо, а левой ссылки у десятки нет. Ключ 10 записывается в корень, затем 10 удаляется из правого поддерева: у этого узла один ребёнок 14, и поддерево 14 с узлом 13 поднимается на его место. Получается дерево с корнем 10, детьми 3 и 14, ниже — 1, 6, 13 и на последнем уровне 4 и 7. Через предшественника получилось бы другое корректное дерево: максимум левого поддерева 7 — лист, он переходит в корень. In-order у обоих деревьев один: 1 3 4 6 7 10 13 14.

Типичные дефекты удаления: при удалении корня не обновляется `self.root`; при удалении узла с одним ребёнком теряется поддерево; преемника после копирования ключа удаляют поиском от корня — но в удаляемом узле уже лежит ключ преемника, и поиск снова находит этот же узел.

## 8. Проверка инварианта BST

Проверка «каждый узел больше левого ребёнка и меньше правого» неверна. Пусть у корня 5 левый ребёнок 3 и правый 8, а у тройки — правый ребёнок 7. Локальная проверка проходит: 3 < 5, 8 > 5, 7 > 3. Но 7 лежит в левом поддереве пятёрки, и дерево сломано: `search(7)` сравнивает 7 с 5, уходит вправо к 8 и сообщает, что ключа нет, хотя он в дереве есть. In-order этого дерева — 3, 7, 5, 8 — не возрастает, и правильная проверка ловит ошибку сразу:

```python
def is_bst(tree):
    a = tree.in_order()
    return all(x < y for x, y in zip(a, a[1:]))
```

Другой способ — рекурсия с границами: каждый узел получает интервал, в котором должен лежать его ключ; левый ребёнок наследует от родителя верхнюю границу, правый — нижнюю.

Реализацию операций проверяют сверкой с эталоном: случайная последовательность вставок и удалений выполняется одновременно в дереве и во встроенном `set`, и после каждой операции `in_order()` должен совпасть с `sorted()` эталона.

## 9. Высота дерева и порядок вставки

Поиск, вставка, удаление, минимум и преемник стоят O(h), а высота лежит в пределах **⌊log₂ n⌋ ≤ h ≤ n − 1**. Наименьшая высота — у дерева, где заполнены все уровни, кроме последнего; наибольшая — у цепочки, где у каждого узла один ребёнок. Для тысячи ключей это 9 или 999, для миллиона — 19 или 999 999. Цепочка — это связный список: поиск в ней перебирает узлы по одному. Время операций BST определяет высота, а не число узлов.

Высота зависит от порядка вставок. Ключи 1, 2, …, 7 в порядке 4, 2, 6, 1, 3, 5, 7 дают идеальное дерево высоты 2, в порядке 3, 1, 6, 2, 5, 7, 4 — дерево высоты 3, а по возрастанию — цепочку высоты 6. Все 5 040 порядков этих ключей дают 429 различных деревьев:

| Высота | 2 | 3 | 4 | 5 | 6 |
| --- | --- | --- | --- | --- | --- |
| Порядков вставки | 80 | 2 240 | 2 048 | 608 | 64 |

Средняя высота по всем порядкам — 3,67. Порядок вставки даёт данное дерево, если в каждом поддереве первым вставлен его корень; для поддерева из s узлов это происходит с вероятностью 1/s, поэтому число порядков равно n!/Π s(v) — произведение по всем узлам размеров их поддеревьев. Для идеального дерева из 7 ключей это 5040 / (7·3·3) = 80. Цепочку дают 2⁶ = 64 порядка: каждый следующий ключ — минимум или максимум оставшихся. Упорядоченный и обратный порядок — два из них, и как раз они часто встречаются на практике: номера заказов, отметки времени, автоинкрементные идентификаторы растут.

### Разбор 2. Сумма глубин случайного дерева

Пусть все n! порядков вставки равновероятны. Ключ при вставке сравнивается со всеми будущими предками, поэтому сравнений при построении столько, какова сумма глубин узлов. Обозначим её среднее D(n):

```
D(0) = D(1) = 0
корень — k-й по величине ключ с вероятностью 1/n;
слева k − 1 узлов, справа n − k; каждый из n − 1 некорневых узлов
на 1 глубже, чем в своём поддереве:
D(n) = n − 1 + (1/n)·Σ (D(k−1) + D(n−k))
     = 2(n + 1)·H(n) − 4n ≈ 2n·ln n ≈ 1,39·n·log₂ n
H(n) = 1 + ½ + … + 1/n
```

Это в точности среднее число сравнений QuickSort из [Лекции 3](lecture-03-simple-sorts-quicksort.md): первый вставленный ключ становится корнем, как первый опорный элемент, меньшие ключи уходят влево, большие — вправо. Два ключа сравниваются при построении дерева, только если один из них стал предком другого, а это происходит, когда из всех ключей между ними первым вставлен один из этих двух; в QuickSort условие сравнения то же самое. Проверка при n = 3: из шести порядков четыре дают цепочки с суммой глубин 3, а два (2, 1, 3 и 2, 3, 1) — дерево с суммой 2; среднее 16/6 = 8/3, и по формуле 2·4·(1 + ½ + ⅓) − 12 = 8/3.

Средняя глубина узла, следовательно, около 2·ln n ≈ 1,39·log₂ n. Эксперимент на 100 случайных деревьях из 10⁴ ключей: средняя глубина узла 15,54 (по формуле 15,58), высота в среднем около 30 — от 26 до 37. Высота тоже растёт как Θ(log n), но с большей константой: самый глубокий узел примерно вдвое глубже среднего. У идеального дерева из 10⁴ ключей высота 13, у цепочки — 9 999.

Случайный порядок — предположение о входе, а не свойство алгоритма. В QuickSort случайный опорный выбирает сам алгоритм, и гарантия работает на любом входе; ключи дерева приходят по одному, и перемешать их заранее нельзя. На упорядоченных данных обычное дерево поиска вырождается в цепочку.

## 10. AVL-деревья

Сбалансированное дерево поиска сохраняет высоту O(log n) при любой последовательности операций. Первое такое дерево предложили Г. М. Адельсон-Вельский и Е. М. Ландис в 1962 году.

**Определение.** AVL-дерево — бинарное дерево поиска, в котором у каждого узла высоты левого и правого поддеревьев различаются не больше чем на единицу.

Показатель сбалансированности узла — bf(v) = h(left) − h(right); в AVL-дереве он равен −1, 0 или +1, а высота пустого поддерева, как и раньше, −1. В каждом узле хранят высоту его поддерева — одно целое число. Дерево из раздела 3 — BST, но не AVL-дерево: у узла 10 левое поддерево пустое (высота −1), а правое имеет высоту 1, bf(10) = −2.

Идеальный баланс — все уровни заполнены, кроме последнего, — поддерживать слишком дорого: после одной вставки дерево иногда приходится перестраивать почти целиком, Θ(n). Условие AVL слабее, но восстанавливается за O(log n) и всё равно гарантирует логарифмическую высоту.

### Разбор 3. Оценка высоты AVL-дерева

Пусть N(h) — наименьшее число узлов в AVL-дереве высоты h. У такого дерева одно поддерево корня имеет высоту h − 1, другое — h − 2, и оба тоже наименьшие:

```
N(0) = 1,  N(1) = 2,  N(h) = N(h−1) + N(h−2) + 1
M(h) = N(h) + 1:  M(h) = M(h−1) + M(h−2)
M(0) = 2 = F(3),  M(1) = 3 = F(4)
⇒ N(h) = F(h + 3) − 1        (F — числа Фибоначчи, F(1) = F(2) = 1)
F(m) ≥ φ^(m−2), φ = (1 + √5)/2 ≈ 1,618  (индукция: φ² = φ + 1)
n ≥ N(h) ≥ φ^(h+1) − 1  ⇒  h + 1 ≤ log_φ(n + 1) = log₂(n + 1)/log₂ φ
h ≤ 1,4404·log₂(n + 1) − 1
```

| h | 0 | 1 | 2 | 3 | 4 | 5 | 10 | 27 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| N(h) | 1 | 2 | 4 | 7 | 12 | 20 | 232 | 832 039 |
| 2^(h+1) − 1 | 1 | 3 | 7 | 15 | 31 | 63 | 2 047 | 268 435 455 |

Итог: **h ≤ 1,44·log₂ n**; более точная оценка Д. Кнута — h < 1,4405·log₂(n + 2) − 1,3277 (высота в рёбрах). Наименьшее AVL-дерево высоты h растёт как φʰ, идеальное — как 2ʰ, поэтому AVL-дерево не более чем в 1,44 раза выше идеального: из миллиона ключей — не выше 27 против 19 у идеального.

## 11. Повороты, вставка и удаление в AVL-дереве

Поворот вправо вокруг узла y с левым ребёнком x поднимает x наверх и опускает y вправо. Пусть A и B — поддеревья x, C — правое поддерево y. После поворота A остаётся у x, C — у y, а B переходит от x к y как его левое поддерево. Порядок in-order до и после одинаков — A, x, B, y, C, — потому что ключи B больше x и меньше y. Поворот влево вокруг x — обратная операция.

```python
def h(node):
    return node.height if node else -1

def update(node):
    node.height = 1 + max(h(node.left), h(node.right))

def rotate_right(y):
    x = y.left
    y.left = x.right              # поддерево B
    x.right = y
    update(y)                     # сначала нижний узел
    update(x)
    return x                      # новый корень поддерева
```

Поворот меняет три ссылки (с учётом ссылки родителя) и пересчитывает высоты двух узлов — O(1).

Вставка в AVL-дерево — обычная вставка в BST, после которой на пути к корню пересчитываются высоты. В первом узле z, где |bf| = 2, выполняется балансировка; случай называют по пути от z к новому ключу:

| Случай | Куда вставлен ключ | Балансировка |
| --- | --- | --- |
| LL | в левое поддерево левого ребёнка z | поворот вправо вокруг z |
| RR | в правое поддерево правого ребёнка z | поворот влево вокруг z |
| LR | в правое поддерево левого ребёнка z | влево вокруг ребёнка, затем вправо вокруг z |
| RL | в левое поддерево правого ребёнка z | вправо вокруг ребёнка, затем влево вокруг z |

```python
def rebalance(z):
    update(z)
    if h(z.left) - h(z.right) == 2:               # перевес слева
        if h(z.left.left) < h(z.left.right):      # случай LR
            z.left = rotate_left(z.left)
        return rotate_right(z)                    # LL
    if h(z.right) - h(z.left) == 2:               # перевес справа
        if h(z.right.right) < h(z.right.left):    # случай RL
            z.right = rotate_right(z.right)
        return rotate_left(z)                     # RR
    return z
```

После вставки достаточно **одной** балансировки, одиночной или двойной: вставка подняла поддерево z на единицу, а поворот возвращает ему прежнюю высоту, поэтому выше по пути баланс не нарушен. Вставка в AVL-дерево стоит O(log n) в худшем случае. При 10⁵ случайных вставках балансировка понадобилась 46 805 раз — 0,47 на вставку, одиночных и двойных примерно поровну.

Пример двойного поворота: после вставок 50, 20, 70, 10, 30 вставляется 25. В узле 50 перевес слева (+2), а у его левого ребёнка 20 — справа (−1): случай LR. Поворот влево вокруг 20 поднимает 30, и 25 переходит к 20 правым ребёнком; поворот вправо вокруг 50 делает 30 корнем с детьми 20 и 50, у 20 — дети 10 и 25, у 50 — правый ребёнок 70. Одного поворота вправо вокруг 50 мало: получилось бы дерево 20(10, 50(30(25), 70)) с bf(20) = −2.

Упорядоченные ключи AVL-дереву не страшны. При вставке 1, 2, …, 7 выполняются четыре балансировки RR — в узлах 1, 3, 2 и 5, — и получается идеальное дерево высоты 2 с корнем 4, тогда как обычное BST на тех же вставках — цепочка высоты 6. Десять тысяч упорядоченных ключей дают AVL-дерево высоты 13 = ⌊log₂ n⌋.

Удаление выполняется как в BST, затем на пути к корню пересчитываются высоты и балансируется каждый узел, где |bf| = 2. В отличие от вставки, поворот после удаления может уменьшить высоту поддерева, и дисбаланс переходит выше: балансировок бывает несколько — до одной на уровень, O(log n). Пример: в наименьшем AVL-дереве высоты 4 (12 узлов, корень 8, правое поддерево 11 с детьми 10 и 12, у 10 левый ребёнок 9) удаление листа 12 вызывает поворот вправо вокруг 11, а затем — из-за потерянного уровня — поворот вправо вокруг корня 8. Время удаления остаётся O(log n).

Цена балансировки — высота в каждом узле, пересчёт на пути вверх и повороты; зато дерево не вырождается. Замер на Python (порядок величин): для 10⁵ случайных ключей обычное дерево имеет высоту 40, AVL — 19; AVL строится дольше (0,36 с против 0,10 с), но ищет быстрее (все ключи — 67 мс против 89 мс). Для 10⁴ упорядоченных ключей обычное дерево — цепочка высоты 9 999, построение занимает около 1,5 с, поиск всех ключей — 1,4 с; AVL-дерево высоты 13 строится за 29 мс и находит все ключи за 4 мс.

Другие сбалансированные деревья: красно-чёрные держат баланс слабее (высота не больше 2·log₂(n + 1)), но при вставке им достаточно не больше двух поворотов — на них построены `TreeMap` в Java и `std::map` в распространённых реализациях C++. Индексы СУБД и файловые системы используют B-деревья: в узле лежат сотни ключей, одно чтение блока с диска отсекает сотни вариантов, и дерево из миллионов записей имеет высоту 3–4.

| Структура | Поиск | Вставка и удаление | Обход по порядку |
| --- | --- | --- | --- |
| Упорядоченный массив | O(log n) | Θ(n) | Θ(n) |
| BST, случайный порядок вставок | O(log n) в среднем | O(log n) в среднем | Θ(n) |
| BST, худший случай | Θ(n) | Θ(n) | Θ(n) |
| AVL-дерево | O(log n) | O(log n) | Θ(n) |
| Хеш-таблица (лекция 8) | O(1) в среднем | O(1) в среднем | нужна сортировка: Θ(n log n) |

В стандартной библиотеке Python сбалансированного дерева нет. Если порядок ключей не нужен, используют `set` и `dict`; упорядоченные данные, которые меняются редко, хранят в отсортированном списке и ищут модулем `bisect`. Константы в Python велики: на 10⁵ случайных ключах поиск `bisect` по списку (около 23 мс на все ключи) быстрее любого дерева на чистом Python, хотя асимптотика у них одинаковая, — O-оценка описывает рост, а не время при конкретном n.

## Вопросы для самопроверки

1. Какие порядки вставки ключей 1, 2, 3 дают дерево высоты 1?
2. Какой ключ окажется в корне, если удалить 8 из дерева, полученного вставками 8, 3, 10, 1, 6, 14, 4, 7, 13?
3. Сколько узлов минимум в AVL-дереве высоты 5?

<details>
<summary>Ответы</summary>

1. Два порядка: 2, 1, 3 и 2, 3, 1. Дерево высоты 1 из трёх ключей — корень с двумя детьми, поэтому корнем должна быть двойка; после неё единица и тройка встают по разные стороны в любом порядке. Остальные четыре порядка дают цепочки высоты 2.
2. 10. У восьмёрки два ребёнка, поэтому её заменяет преемник — минимум правого поддерева; правое поддерево начинается с десятки, а левой ссылки у неё нет. Ключ 10 переходит в корень, а прежний узел 10 удаляется по второму случаю: на его место поднимается 14 вместе с 13.
3. Двадцать: N(0) = 1, N(1) = 2, далее N(h) = N(h − 1) + N(h − 2) + 1 даёт 4, 7, 12, 20. По формуле N(5) = F(8) − 1 = 21 − 1 = 20.

</details>
