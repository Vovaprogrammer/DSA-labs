## 1. Рекурсивные функции

Нужно реализовать четыре рекурсивные функции (`factorial`, `fib_naive`,
`fib_memo`, `hanoi`), вывести для каждой оценку сложности и подтвердить её
счётчиком вызовов (для Фибоначчи) и проверкой числа ходов (для Ханойских
башен). Здесь сравниваются не времена, а **числа вызовов**: они не зависят
от железа, поэтому таблица ниже воспроизводится на любой машине.

### 1.1 Факториал — `factorial`

```python
def factorial(n: int) -> int:
    if n < 0:
        raise ValueError("Нельзя считать факториал для отрицательных чисел!")
    if n == 0:
        return 1
    return n * factorial(n - 1)
```

**Θ(n).** Базовый случай — `n == 0`, шаг уменьшает `n` на 1, всего n + 1
вызовов и n умножений. Глубина стека вызовов тоже n + 1, поэтому память
Θ(n), а при `n`, близком к пределу глубины рекурсии CPython (около 1000
кадров), функция упадёт с `RecursionError`.

**Корректность** — индукцией: `factorial(0) = 1 = 0!`; если
`factorial(n-1) = (n-1)!`, то `n · factorial(n-1) = n!`.

**Завершение.** Мера — `n`: это неотрицательное целое, которое строго
уменьшается при каждом вызове, поэтому цепочка вызовов конечна. Для `n < 0`
эта мера ломается (базовый случай `n == 0` проскакивается, вызовы шли бы до
`RecursionError`), поэтому отрицательные аргументы отсекаются явным
`ValueError` до рекурсии.

### 1.2 Числа Фибоначчи наивно — `fib_naive`

```python
def fib_naive(n: int) -> int:
    CALLS["fib_naive"] += 1
    if n < 2:
        return n
    return fib_naive(n - 1) + fib_naive(n - 2)
```

**Θ(φⁿ), φ = (1 + √5)/2 ≈ 1,618.** Обозначим C(n) число вызовов при
вычислении `fib_naive(n)`, считая первый:

```
C(0) = C(1) = 1,   C(n) = C(n−1) + C(n−2) + 1   при n ≥ 2
```

Слагаемое «+1» мешает увидеть числа Фибоначчи, поэтому перейдём к
D(n) = C(n) + 1:

```
D(n) = C(n−1) + C(n−2) + 2 = (C(n−1) + 1) + (C(n−2) + 1) = D(n−1) + D(n−2)
D(0) = 2 = 2·F(1),   D(1) = 2 = 2·F(2)
```

D(n) и 2·F(n+1) подчиняются одному правилу «сумма двух предыдущих» и
совпадают при n = 0 и n = 1, значит, совпадают при всех n:

**C(n) = 2·F(n+1) − 1.**

Так как F(n) ≈ φⁿ/√5, получаем C(n) ≈ (2φ/√5)·φⁿ ≈ 1,45·φⁿ = Θ(φⁿ).
Причина роста — повторные подзадачи: `fib_naive(n-2)` вычисляется и внутри
`fib_naive(n-1)`, и отдельно.

Память при этом только Θ(n): в стеке лежит один путь от корня дерева
вызовов до текущего вызова, не больше n кадров.

### 1.3 Числа Фибоначчи с мемоизацией — `fib_memo`

```python
def fib_memo(n: int, memo: dict[int, int] | None = None) -> int:
    CALLS["fib_memo"] += 1
    if memo is None:
        memo = {}
    if n in memo:
        return memo[n]
    if n < 2:
        return n
    memo[n] = fib_memo(n - 1, memo) + fib_memo(n - 2, memo)
    return memo[n]
```

**Θ(n).** Словарь `memo` передаётся вниз по рекурсии, поэтому каждое
значение k = 2, …, n вычисляется ровно один раз, и это вычисление порождает
два рекурсивных вызова. Остальные входы в функцию (базовые случаи и
попадания в кэш) новых вызовов не порождают. Счётчик считает все входы, в
том числе попадания в кэш, поэтому:

**M(n) = 1 + 2·(n − 1) = 2n − 1**   при n ≥ 1.

Значение по умолчанию `memo=None`, а не `memo={}`: изменяемый аргумент по
умолчанию создаётся один раз на всё время жизни функции и делил бы кэш
между несвязанными вызовами (и «смазал» бы счётчик при повторных замерах).

### 1.5 Ханойские башни — `hanoi`

```python
def hanoi(n: int, src: str = "A", dst: str = "C", aux: str = "B",
          moves: list[tuple[str, str]] | None = None) -> int:
    if n == 0:
        return 0
    count = hanoi(n - 1, src, aux, dst, moves)   # шаг 1: n-1 дисков src -> aux
    if moves is not None:
        moves.append((src, dst))                 # шаг 2: большой диск src -> dst
    count += 1
    count += hanoi(n - 1, aux, dst, src, moves)  # шаг 3: n-1 дисков aux -> dst
    return count
```

**Идея.** Чтобы перенести n дисков, нужно убрать n − 1 верхних дисков на
вспомогательный стержень, одним ходом переложить самый большой диск на
целевой стержень и вернуть n − 1 дисков сверху. Оба переноса на n − 1
дисков — та же задача, но с другими ролями стержней:

| Шаг | откуда | куда | вспомогательный | аргументы `(src, dst, aux)` |
|---|---|---|---|---|
| 1 | `src` | `aux` | `dst` | `(src, aux, dst)` |
| 3 | `aux` | `dst` | `src` | `(aux, dst, src)` |

Список `moves` передаётся во все рекурсивные вызовы тот же самый (не срез
и не копия), а ход самого большого диска дописывается **между** двумя
рекурсивными вызовами: именно в таком порядке ходы допустимы.

**Число ходов.** Пусть T(n) — число ходов. Два переноса n − 1 дисков плюс
один ход самым большим диском: T(0) = 0, T(n) = 2·T(n−1) + 1.

```
T(n) = 2·T(n−1) + 1 = 4·T(n−2) + 2 + 1 = 8·T(n−3) + 4 + 2 + 1 = …
     = 2ᵏ·T(n−k) + (2ᵏ − 1)
k = n:  T(n) = 2ⁿ·T(0) + 2ⁿ − 1 = 2ⁿ − 1
```

Это Θ(2ⁿ). Оценка **точная**, а не «неудачность реализации»: число ходов
именно 2ⁿ − 1, и рост экспоненциальный уже по числу ходов самой задачи, а
не из-за повторных подзадач, как в `fib_naive`. Поэтому мемоизация здесь не
поможет: каждый ход нужно физически выполнить.

Число вызовов `hanoi` при этом — 2ⁿ⁺¹ − 1: 2ⁿ − 1 внутренних узлов дерева
вызовов (в каждом ровно один ход) плюс 2ⁿ пустых вызовов `n == 0` на листьях,
то есть тоже Θ(2ⁿ); глубина стека n + 1.

| n | ходов, `hanoi(n)` | 2ⁿ − 1 |
|---|---|---|
| 0  | 0    | 0    |
| 1  | 1    | 1    |
| 2  | 3    | 3    |
| 3  | 7    | 7    |
| 5  | 31   | 31   |
| 10 | 1023 | 1023 |

Ходы для n = 3 (A → C, вспомогательный B):

```
(A,C) (A,B) (C,B) | (A,C) | (B,A) (B,C) (A,C)
```

Первые три хода переносят два малых диска на B, четвёртый переносит
большой диск на C, последние три возвращают малые диски сверху.

Ханойские башни и числа Фибоначчи — это «уменьшай и властвуй» (задача
уменьшается на 1 или 2, а не делится в b раз), поэтому мастер-теорема к их
рекуррентам неприменима; они раскрываются напрямую, как выше.

### 1.6 Верификация

По методике `docs/ai-verification.md`; проверки собраны в `self_check()`
(раздел «рекурсия»).

**Инварианты.**

| Функция | Инвариант |
|---|---|
| `hanoi` | ни один ход не кладёт больший диск на меньший; стержень-источник хода не пуст; в конце все n дисков лежат на `dst` в порядке убывания размера; `len(moves)` равен возвращённому числу ходов |
| `fib_memo` | число вызовов не больше 2n + 1 (иначе `memo` не передаётся в рекурсию) |
| `fib_naive` | число вызовов не меньше F(n): при меньшем счётчике это не наивная рекурсия |

**Репрезентативные тесты.**

- `factorial`: n = 0, 1, …, 20;
- `fib_naive`: n = 0, 1, …, 20; отдельно число вызовов на n = 20;
- `fib_memo`: n = 0, 1, 2 (граница), 10, 30, 90 (большое n, на котором наивная
  версия не завершилась бы);
- `hanoi`: n = 0, 1, 2, 3, 6, 7, причём с разными именами стержней
  (`"XZY"`, `"PQR"`), чтобы ловить функцию, привязанную к буквам A/B/C;
  проверяется и вызов без `moves`.

**Сравнение с эталоном.** `factorial` сверяется с `math.factorial` для
n = 0…20, `fib_naive`/`fib_memo` — с таблицей чисел Фибоначчи, вычисленной
циклом; число ходов `hanoi` — с 2ⁿ − 1. Кроме того, счётчики вызовов
`fib_naive`/`fib_memo` в таблице 1.4 сверены с выведенными формулами
C(n) = 2·F(n+1) − 1 и M(n) = 2n − 1: расхождений нет.

**Что `self_check` не проверяет и проверено отдельно.** Отрицательный
аргумент `factorial` — явный `ValueError` (сознательное решение, см. 1.1).
