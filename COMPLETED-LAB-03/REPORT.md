## 1. Простые сортировки со счётчиками

Каждая функция сортирует **копию** входа (вход не меняется) и возвращает кортеж `(отсортированный список, число сравнений, число обменов/перемещений)`.

### 1.1. Сортировка пузырьком

```python
def bubble_sort(a: list) -> tuple[list, int, int]:
    """Сортировка пузырьком. Ожидаемая сложность: Θ(n²). В лучшем случае: Θ(n)."""
    comp = 0
    exch = 0
    a = a.copy()
    n = len(a)
    for i in range(n - 1):
        swapped = False
        for j in range(n - 1 - i):
            comp += 1
            if a[j] > a[j + 1]:
                a[j], a[j + 1] = a[j + 1], a[j]
                exch += 1
                swapped = True
        if not swapped:
            break
    return a, comp, exch
```

Сравниваются соседние элементы; за проход наибольший из оставшихся «всплывает» в конец, поэтому каждый следующий проход короче на один элемент. Если за проход не было ни одного обмена, массив уже упорядочен — досрочный выход (он и даёт лучший случай Θ(n)). Сравнение считается на каждую пару соседей, обмен — только реальный.

### 1.2. Сортировка вставками

```python
def insertion_sort(a: list) -> tuple[list, int, int]:
    """Сортировка вставками. Ожидаемая сложность: Θ(n²). В лучшем случае: Θ(n)."""
    comp = 0
    shft = 0
    a = a.copy()
    n = len(a)
    for i in range(1, n):
        x = a[i]
        j = i - 1
        while j >= 0:
            comp += 1
            if a[j] > x:
                a[j + 1] = a[j]
                shft += 1
                j -= 1
            else:
                break
        a[j + 1] = x
    return a, comp, shft
```

Элемент `x = a[i]` вставляется в упорядоченный префикс: бо́льшие элементы сдвигаются вправо, пока не найдётся `a[j] <= x` или не кончится префикс. Сравнением считается каждое вычисление `a[j] > x` (в том числе последнее, остановившее поиск); перемещением — один сдвиг. На упорядоченном входе каждый элемент сравнивается ровно один раз — Θ(n).

### 1.3. Сортировка выбором

```python
def selection_sort(a: list) -> tuple[list, int, int]:
    """Сортировка выбором. Ожидаемая сложность: Θ(n²) — в любом случае."""
    comp = 0
    exch = 0
    a = a.copy()
    n = len(a)
    for i in range(n - 1):
        m = i
        for j in range(i + 1, n):
            comp += 1
            if a[m] > a[j]:
                m = j
        if i != m:
            a[i], a[m] = a[m], a[i]
            exch += 1
    return a, comp, exch
```

На шаге `i` ищется минимум в `a[i..n-1]` и ставится на позицию `i`. Просмотр суффикса всегда полный, поэтому сравнений ровно `n(n-1)/2` на любом входе — отсюда Θ(n²) независимо от данных. Обмен считается только при `m != i`, поэтому обменов не более `n-1`.

### 1.4. Теоретические оценки

Пусть `inv` — число инверсий входа (от 0 до `n(n-1)/2`).

| Сортировка | Сравнения (лучший / худший) | Обмены/сдвиги | Время |
| --- | --- | --- | --- |
| Пузырёк | `n-1` / `n(n-1)/2` | ровно `inv` | Θ(n) лучший, Θ(n²) средний и худший |
| Вставки | `n-1` / `n(n-1)/2` | ровно `inv` | Θ(n) лучший, Θ(n²) средний и худший |
| Выбор | `n(n-1)/2` / `n(n-1)/2` | не более `n-1` | Θ(n²) всегда |

Обмен соседей в пузырьке и сдвиг во вставках убирают ровно одну инверсию, поэтому их число равно `inv`.

### 1.5. Проверка счётчиков на малых входах

Сравнения / обмены (сдвиги); значения получены ручным расчётом и совпадают с выводом программы.

| Вход | Пузырёк | Вставки | Выбор |
| --- | --- | --- | --- |
| `[1, 2, 3, 4, 5]` | 4 / 0 | 4 / 0 | 10 / 0 |
| `[5, 4, 3, 2, 1]` | 10 / 10 | 10 / 10 | 10 / 2 |
| `[2, 1, 2, 1]` | 6 / 3 | 5 / 3 | 6 / 2 |

На упорядоченном входе пузырёк и вставки делают `n-1` сравнений без обменов (лучший случай), выбор — по-прежнему `n(n-1)/2`. На обратном входе обмены пузырька и сдвиги вставок равны `n(n-1)/2 = inv`.

## 2. QuickSort с рандомизированным опорным элементом

```python
def quick_sort(a: list, rng: random.Random | None = None) -> list:
    """QuickSort с выбором опорного через rng.randrange.
    Ожидаемая сложность: в среднем Θ(n log n), в худшем случае Θ(n²)."""
    if rng is None:
        rng = random.Random()
    b = a.copy()

    def partition(lo, hi):
        p = b[hi]  # опорный
        i = lo     # граница: левее i — элементы < p
        for j in range(lo, hi):
            if b[j] < p:
                b[i], b[j] = b[j], b[i]
                i += 1
        b[i], b[hi] = b[hi], b[i]
        return i   # итоговое место опорного

    def sort(lo, hi):
        if lo >= hi:  # 0 или 1 элемент
            return
        k = rng.randrange(lo, hi + 1)
        b[k], b[hi] = b[hi], b[k]
        m = partition(lo, hi)
        sort(lo, m - 1)
        sort(m + 1, hi)

    sort(0, len(b) - 1)
    return b
```

### 2.1. Как это работает

- **Разбиение (схема Ломуто).** `partition` берёт опорный `p = b[hi]`, переносит все элементы меньше `p` в начало отрезка (граница `i`), затем ставит опорный на позицию `i`. После этого опорный стоит на своём окончательном месте: слева от него элементы `< p`, справа — `>= p`.
- **Рекурсия.** `sort(lo, hi)` разбивает отрезок и рекурсивно сортирует левую и правую части; сам опорный в рекурсию не входит. Базовый случай `lo >= hi` (0 или 1 элемент) — это и есть обработка малых подмассивов.
- **Рандомизация.** Перед разбиением случайный элемент отрезка `lo..hi` меняется местами с `b[hi]` и становится опорным. Индекс выбирается через `rng.randrange(lo, hi + 1)` равновероятно из всего отрезка (правая граница в `randrange` не включается, а `hi` — включительно, поэтому `+ 1`). Генератор `rng` передаётся снаружи, поэтому запуск воспроизводим по seed варианта.
- **Копия входа.** Сортируется копия `b = a.copy()`, исходный список не меняется.

### 2.2. Сложность

| Случай | Что происходит | Оценка |
| --- | --- | --- |
| Средний | разбиения в среднем достаточно сбалансированы, глубина рекурсии порядка `log n`, на каждом уровне `Θ(n)` сравнений | Θ(n log n) |
| Худший | опорный на каждом шаге — минимум или максимум отрезка, разбиение `n-1` и `0`: `T(n) = T(n-1) + Θ(n)` | Θ(n²) |

Память (стек рекурсии): в среднем `O(log n)`, в худшем `O(n)`.

### 2.3. Роль рандомизации

При детерминированном выборе (всегда первый или последний элемент) худший случай возникает на **конкретных входах** — упорядоченном и обратно упорядоченном: опорный каждый раз оказывается минимумом или максимумом, и разбиение вырождается в `n-1` и `0`. При случайном выборе время работы больше не зависит от порядка входа: плохой исход (опорный — экстремум отрезка) имеет вероятность около `2/n` на каждом шаге, а длинная цепочка таких исходов подряд маловероятна. Поэтому упорядоченный и обратный входы ведут себя так же, как случайный, и деградация в Θ(n²) становится практически недостижимой.

### 2.4. Ограничение схемы

Схема Ломуто относит элементы, равные опорному, в правую часть. На массиве из многих одинаковых элементов разбиения становятся неравными (вплоть до `n-1` и `0` при полностью одинаковых), и рандомизация от этого не спасает: выбор любого элемента даёт то же значение. Данные варианта — случайные числа из диапазона `[-10⁶, 10⁶]`, дубликатов в них мало, поэтому на замерах это не проявляется. Для массивов с большим числом дубликатов применяют трёхстороннее разбиение (`< p`, `== p`, `> p`).
